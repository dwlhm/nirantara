# Security Policy

## Supported Versions

We provide security updates and patches for the following versions of Nirantara:

| Version | Supported          |
| :------ | :----------------- |
| 1.x.x   | :white_check_mark: |
| < 1.0.0 | :x:                |

---

## Reporting a Vulnerability

The Nirantara team takes the security of our software and user data seriously. If you discover a security vulnerability or potential exploit, please do **NOT** open a public issue.

Instead, please report vulnerabilities via one of the following methods:

1. **GitHub Security Advisories**: Submit a private advisory report directly via GitHub Security tab: `https://github.com/dwlhm/nirantara/security/advisories/new`
2. **Email**: Send a detailed description of the vulnerability to [security@nirantara.org](mailto:security@nirantara.org).

### What to Include in Your Report

To help us triage and investigate the issue efficiently, please include:
- A clear description of the vulnerability and its potential impact.
- Steps to reproduce the issue (proof-of-concept code, sample payloads, or screen recordings where appropriate).
- The device model, Android OS version, and exact application build version/hash.
- Any suggestions for remediation or mitigation.

### Response Timelines

- **Acknowledgment**: Within 48 hours of initial report receipt.
- **Initial Assessment & Triage**: Within 5 business days.
- **Fix & Disclosure**: We will coordinate the release date of patches with the reporter to ensure users have adequate time to update before public disclosure.

---

## Bounty & Attribution

While Nirantara is an open-source, community-driven project without a commercial bug bounty fund, we gladly acknowledge security researchers in our release notes and GitHub Security Advisories for responsible disclosure.
